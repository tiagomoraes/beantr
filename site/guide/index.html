Install

Install guide.

A skill your assistant loads, plus a folder of coffee notes it reads and writes. Installing puts both in place.

Fastest path One command By agent From a clone Your notes Update Uninstall

The fastest path

Hand the install to the assistant itself. Paste this to any assistant that can run a shell command:

Paste this to your agent

Install Beantr so you can keep track of my coffee. Run curl -fsSL https://beantr.tiagomoraes.cloud/install | bash -s -- all. It adds the Beantr skill and creates my coffee notes at ~/beantr. Then read them and tell me you are ready.

It downloads the pack, installs the skill for every assistant it finds on the machine, and creates your notes at ~/beantr. Existing notes are never overwritten, so it is safe to run again.

Inside Claude Code you can skip the shell entirely and install Beantr as a plugin:

Claude Code
/plugin marketplace add tiagomoraes/beantr
/plugin install beantr@beantr

One command, by hand

The bootstrap installer is a small script served from this site. It downloads the latest pack and hands off to the installer inside it. Beantr installs one assistant at a time, so you name the one you want, or pass all:

shell
# show which assistants it detects, and how to install each (installs nothing)
curl -fsSL https://beantr.tiagomoraes.cloud/install | bash

# install for one assistant, with the default notes folder
curl -fsSL https://beantr.tiagomoraes.cloud/install | bash -s -- claude-code

# install for every assistant it detects, sharing one notes folder
curl -fsSL https://beantr.tiagomoraes.cloud/install | bash -s -- all

# keep the notes somewhere else
curl -fsSL https://beantr.tiagomoraes.cloud/install | bash -s -- hermes ~/coffee

Assistant names: hermes, claude-code, opencode, openclaw, cowork, generic. Every install also writes ~/.beantr/beantr.md, a copy of the skill you can point any other tool at, and ~/.beantr/config with the path to your notes.

By agent

Each assistant has its own page with the prompt, the command and a note for the assistant itself. This is what the installer does for each.

Claude Code

Easiest as a plugin: this repository is its own plugin marketplace, so the two /plugin commands above are the whole install. Claude Code loads the skill on its own whenever you talk about coffee.

Without plugin support, run the shell installer with claude-code. It copies the skill into ~/.claude/skills/beantr, adds a short managed block to ~/.claude/CLAUDE.md as a reminder of where your notes live, and creates the notes. To keep it project-local instead, copy skills/beantr/ into that project's .claude/skills/.

Hermes

Hermes supports skills directly. The installer copies the skill into ~/.hermes/skills/beantr and creates your notes. Load it with hermes --skills beantr, or just ask about coffee.

OpenCode

OpenCode reads the same SKILL.md format as Claude Code and also reads AGENTS.md. The installer copies the skill into ~/.config/opencode/skills/beantr and appends a managed Beantr block to ~/.config/opencode/AGENTS.md. If you already installed for Claude Code on the same machine, OpenCode picks that skill up on its own.

OpenClaw

OpenClaw connects chat apps to an agent and loads skills globally. The installer copies the skill into ~/.openclaw/skills/beantr, where every agent it runs can see it. To force it into the system prompt on every turn, paste installers/snippets/openclaw.md into your workspace AGENTS.md.

Claude Cowork

Cowork takes skills as an upload in the desktop app. The installer packages the skill as dist/beantr-skill.zip and creates your notes. Then open Settings → Cowork → Customize → Skills, choose + → Upload a skill, pick the zip, and grant Cowork access to your ~/beantr folder.

Any other assistant

Run the installer with generic. It creates the notes and writes the skill to ~/.beantr/beantr.md. Then tell your assistant:

Use Beantr. Read ~/.beantr/beantr.md, then manage my coffee notes at ~/beantr by updating the current files and appending to the monthly logs.

From a clone or the pack

Want to read the pack before running it, or install from CI? Clone the repository, or download the same pack the bootstrap script uses, and run the installer directly. The bootstrap script and the plugin both wrap this.

shell
# clone
git clone https://github.com/tiagomoraes/beantr.git
cd beantr

# or download the pack
curl -L https://beantr.tiagomoraes.cloud/beantr-agent-pack-latest.tar.gz | tar xz
cd beantr

# then install: ./installers/install.sh <agent> [notes-path]
./installers/install.sh hermes ~/beantr

The installer only copies Markdown and shell files into places each assistant already reads: skills folders, CLAUDE.md, AGENTS.md. For Cowork it packages a zip. Run it with no arguments to list what it detects without installing anything.

Where your notes live

By default at ~/beantr, created from starter templates the first time. Every file is Markdown you can open and edit yourself. The assistant keeps the current files up to date and only ever adds to the monthly logs.

~/beantr/
  README.md
  beans/current.md            # what is on the shelf right now
  beans/history/2026-09.md    # restocks and corrections, month by month
  gear/current.md             # grinders, brewers, defaults
  gear/history/2026-09.md
  recipes/current.md          # the recipe you would reach for today
  sessions/2026-09.md         # every brew, month by month
  insights/current.md         # what to try next, only when your cups back it up

Pass a different folder as the last argument of any install command to keep the notes elsewhere. The path is remembered in ~/.beantr/config, so updates find it. Full detail on each file is in the ledger reference.

Updating

An update re-applies the latest pack to the assistants you already installed for. It refreshes the skill, the managed blocks and ~/.beantr/beantr.md, adds any new starter file a release introduces, and never moves or overwrites your notes.

shell
# Claude Code plugin
/plugin update beantr@beantr

# everyone else: every installed assistant, or just one
curl -fsSL https://beantr.tiagomoraes.cloud/update | bash
curl -fsSL https://beantr.tiagomoraes.cloud/update | bash -s -- claude-code

# from a clone or pack
git pull && ./installers/update.sh

Cowork and generic installs are not auto-detected, so name them: ./installers/update.sh cowork repackages the zip for you to upload again. The update prints what changed, for example Beantr updated: v1.2.0 -> v2.0.0.

Uninstalling

Uninstalling mirrors installing: it removes only what the installer added. Your notes are your data and are never deleted; the script prints their location on the way out.

shell
# Claude Code plugin (second line optional)
/plugin uninstall beantr@beantr
/plugin marketplace remove beantr

# everyone else: list what is installed (removes nothing), one assistant, or all
curl -fsSL https://beantr.tiagomoraes.cloud/uninstall | bash
curl -fsSL https://beantr.tiagomoraes.cloud/uninstall | bash -s -- claude-code
curl -fsSL https://beantr.tiagomoraes.cloud/uninstall | bash -s -- all
AssistantRemoved
hermes~/.hermes/skills/beantr
claude-code~/.claude/skills/beantr and the managed block in ~/.claude/CLAUDE.md
opencode~/.config/opencode/skills/beantr and the managed block in that AGENTS.md
openclaw~/.openclaw/skills/beantr. Remove any snippet you pasted into a workspace AGENTS.md yourself
coworkdist/beantr-skill.zip. Delete the uploaded skill in Cowork's Customize panel
generic~/.beantr/README.md

When the last assistant is removed, the shared files in ~/.beantr are cleaned up too. If you truly want your coffee history gone, that is one more command you run yourself: rm -rf ~/beantr.
